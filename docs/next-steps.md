# 开发顺序与待确认信息

## 开发顺序

1. 登录、团队和角色权限、账号停用与会话撤销、密钥管理及权限测试。
2. 7 字段手工录入、粘贴解析确认、敏感字段加密/HMAC 去重、我的线索。
3. 分配事务、咨询接收、限时查看和审计；并发提交不能重复分配。
4. 回访、预约、到院、核验成交及事件时间轴。
5. Excel 模板/逐行错误报告、主管超时/重复/转派、站内提醒。
6. 历史漏斗、维度筛选、备份恢复与小团队试运行。
7. 第二阶段接平台授权、企业微信/SCRM、院内核验；AI 私信解析只做建议并由人确认。

## 还需业务提供

| 信息 | 骨架默认/处理 | 何时需要 |
|---|---|---|
| 团队及人员角色、主管范围 | 不添加真实账号 | 登录与权限开发前 |
| 病种、渠道、区域、院区、项目与原因字典 | 表结构就绪，不假定具体清单 | 录入页面开发前 |
| 咨询能力、值班、权重、两种容量 | 开发默认权重1/日20/跟进50 | 分配试运行前 |
| 重复窗口与归属、无效计数是否冲减 | 疑似重复由主管审核 | 去重与分配计数实现前 |
| 接收、首联、回访、沉默时限 | 接收5分钟、首联15分钟；其余待定 | 异常任务开发前 |
| 运营能否看单条金额 | 默认仅汇总 | 看板开发前 |
| 部署环境、数据库、域名及访问范围 | Python+SQLite 本地骨架 | 生产部署前 |
| 脱敏样例、录入格式、Excel 样本 | 仅人工入口契约 | 解析/导入开发前 |
| 平台/企业微信授权与院内接口 | 不要求提供密码到公开仓库 | 第二阶段接入前 |
| 数据告知、保存/删除期限和权限责任 | 不录入真实患者资料 | 真实试运行前 |

以上待确认不阻塞当前项目骨架。下一开发默认从登录权限与手工录入开始；算法、时限和金额可见性尚未视作已确认。

## 验收

- 两个运营互相无法通过列表、搜索、ID 访问对方数据。
- 咨询接收前不解密，转派后旧咨询立即失权。
- 并发分配、重复提交、接收与超时回收竞争均无双重归属。
- 微信数据库密文、查询脱敏、查看/复制/转派审计，停用撤销会话。
- 未加微信无回访时间不能保存；预约/到院/成交必填结果。
- Excel 错误逐行回报，重复不二次分配。
- 漏斗按历史事件去重，成交经过核验，退款影响净收入。

当前测试仅验证纯函数分配和建表，不代表以上业务验收已通过。
