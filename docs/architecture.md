# 架构与模块

本地骨架使用 Python 标准库与 SQLite，便于立即验证启动和数据模型。后续建议 Python API 框架 + 响应式前端 + PostgreSQL + 定时任务；框架选择尚未锁定，不影响业务边界。当前没有第三方平台或 AI 模型调用。

|---|---|---|

| 线索中台 | 7字段录入、粘贴确认、Excel导入、联系方式去重 | 表与合约；API待实现 |

## 分配事务设计

1. 服务端验证当前用户、团队和线索版本，拒绝重复待处理线索。
2. 开启事务（SQLite BEGIN IMMEDIATE；PostgreSQL 使用行锁与团队/日期分配锁）。
3. 查询匹配咨询，按上海自然日统计有效分配数，检查当日容量和超时阻断。
4. 调用候选选择函数；同分时按上次分配时间和用户ID排序。
5. 结束旧分配记录，插入新记录，更新线索归属/状态/版本、咨询上次分配时间。
6. 同事务追加状态记录、审计和站内通知；提交后发送外部通知。

候选选择函数自身没有数据库锁，不能直接当生产分配服务。有效分配计数定义待业务确认，避免因无效回填滥用配额。转派必须写原因，不覆盖原运营归属。接收时间属于本次分配，转派必须清除线索 accepted_at。

## 数据安全实现边界

- 查询统一加入角色与团队条件，写入再次鉴权；禁止前端自报创建人/角色/团队。
- 联系方式应用层认证加密（建议 AES-GCM）；密钥使用独立密钥管理，不提交 Git。去重用独立密钥 HMAC，不能用普通哈希代替。原始私信默认不入库；如需保存，先定义加密、脱敏与保留期限。
- 接收后查看为独立接口，鉴权与审计成功后才解密。响应 no-store，前端限时隐藏和水印。隐藏不代表可以撤回已泄露的数据。
- 登录使用密码哈希，会话只存令牌哈希；每次请求校验 enabled 与 session_version，停用同步撤销。
- 审计不写微信、手机号、原始私信或解密数据。SQLite 触发器不能防数据库管理员篡改；正式环境应隔离写权限和备份。
- 未接入真实患者数据；上线前完成授权、权限、加密、备份恢复、敏感日志和并发测试。

## 开发顺序与验收

1. 认证/权限/加密：跨运营、跨咨询、跨团队访问被拒绝；停用立即失效。
2. 录入/去重：运营由会话确定；必填与字典类型校验；重复不重复分配。
3. 分配/接收：并发提交不双分配、不超容量；转派后旧咨询不可查看。
4. 咨询闭环：必填结果校验，记录事件、金额、核验与回访任务。
5. 异常/导入/驾驶舱：任务幂等；导入逐行错误；经营数据可按历史事件复算。

已有测试覆盖纯规则与关键数据库约束；认证、加密、并发和完整闭环验收尚未完成。
