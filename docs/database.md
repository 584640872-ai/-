# 数据库设计

可执行 DDL：db/migrations/001_initial.sql。迁移记录表 schema_migrations 由初始化脚本创建。当前不生成真实或模拟患者，也不内置登录密码。

| 表 | 关键字段/关系 | 用途 |
|---|---|---|
| teams / users | 团队、角色、enabled、session_version | 组织及即时停用 |
| sessions | token_hash、expires_at、revoked_at | 会话撤销 |
| dictionaries / hospitals | kind+code唯一、区域/院区 | 病种、渠道、区域、原因 |
| consultant_profiles | 权重1–10、容量、值班 | 接待规则 |
| consultant_diseases / consultant_regions | 咨询+字典复合主键 | 能力、区域匹配；区域空集合代表不限 |
| leads | 唯一编号、创建人、加密微信/HMAC、当前咨询、状态、版本 | 7核心字段、来源与归属 |
| assignments | 原/新咨询、规则快照、时限、接收、结束时间 | 不覆盖分配历史；每条最多一条活动记录 |
| state_events | 前后状态、操作者、结果JSON、时间 | 历史漏斗与追溯 |
| consultation_notes | 加密内容、作者 | 咨询备注隔离 |
| followup_tasks | 负责人、计划/完成时间 | 回访待办 |
| appointments / visits | 院区、预约、实际到院、核验 | 可多次预约及到院 |
| deals | 项目、整数分金额、核验、外部收据ID | 可多笔成交，防重复收据 |
| audit_logs | 动作、对象、请求ID、设备、安全元数据 | 追加审计 |
| import_jobs / import_rows | 总数、成功失败、行号、错误码 | 导入报告，不保留原始联系方式 |
| notifications / exception_tasks | 接收人、异常类型、处理原因 | 站内提醒与异常 |
| rule_configs | 配置键、JSON、更新人 | 时限、重复与安全策略 |

## 约束和业务层责任

SQLite 外键每个连接必须启用。字典 kind 必须由业务层验证，不能把渠道ID填进病种字段。联系方式 HMAC 不设唯一约束，因为重复需进入主管复核，而非丢弃原始提交；外部线索ID按渠道去重。编号建议 L+上海日期+数据库ID，禁止用前端计数器。时间统一存 UTC ISO8601；当天容量与报表在 Asia/Shanghai 分组。金额采用整数分，不使用浮点。

查询索引覆盖创建人、咨询员/状态、微信HMAC与时间。更新按 version 乐观锁；主表和事件、分配、审计必须同事务提交。JSON是扩展结果，不替代金额、日期等结构化字段。审计及状态记录禁止普通用户修改/删除；状态事件权限限制仍待实现。删除、归档、保留期和密钥轮换尚待设计。

## 经营口径

默认创建日期队列：以线索创建时间筛选队列，再根据历史事件统计截至查询时点曾达到的接收/加微/预约/到院/成交，不用当前状态直接累加。每阶段按 lead_id 去重；转派不重复算线索数；成交金额按核验成交记录汇总。另做事件发生日期报表，两种日期口径不得混合。

接收及时率=规定时间内接收的分配记录/有效分配记录；加微率=加微线索/接收线索；预约率=预约/加微；到院率=到院/预约；成交率=成交/到院。分母为0返回null。收入与无效率区分已核验、待核验。有效线索及退款口径尚待确认；ROI需要成本账本，当前版本不声称已支持ROI。
