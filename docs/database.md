# 数据库设计

`database/schema.sql` 是可执行 SQLite 开发表结构，不是生产 PostgreSQL/MySQL 迁移。时间统一 UTC ISO-8601；前端和业务日转换到 Asia/Shanghai；ID 建议 UUID。

| 表 | 主要作用/字段 |
|---|---|
| schema_migrations | 首版建表版本 001 |
| teams / users | 团队、角色、启用状态、密码哈希、会话版本 |
| dictionaries | 病种、渠道、区域、无效/转派原因、院区、项目 |
| source_accounts | 渠道账号与运营归属 |
| consultant_profiles | 权重、值班、容量、阻塞、上次分配时间 |
| consultant_skills / consultant_regions | 能力与区域多对多 |
| leads | 7 核心字段、归属、来源、状态、重复关联、版本号 |
| assignments | 原/新咨询、接收、结束时间、原因、规则快照 |
| status_events | 状态前后值、操作者、时间、结构化结果 |
| followups | 回访归属、到期时间和完成结果 |
| appointments | 院区、预约、到院、取消与核验 |
| deals | 项目、整数分金额、退款、核验与成交时间 |
| audit_logs | 操作对象、操作者、时间和脱敏元数据 |
| import_jobs | 导入成功/失败数、错误报告位置 |
| notifications | 站内提醒与唯一幂等键 |
| settings | 配置、接收和首联阈值 |

联系方式字段预留密文 BLOB、密钥版本及 HMAC 查重标识；当前尚未实现加密。生产实现使用成熟的认证加密库与独立密钥管理，查重用独立密钥 HMAC，禁止明文/普通哈希保存微信和手机号。HMAC 非唯一索引以支持重复审核，不能静默覆盖原运营。

活动分配按 lead_id 建部分唯一索引；线索按运营和咨询状态索引。外键开启，金额非负、退款不超过金额、权重 1–10。字典种类、跨团队归属、角色、状态跳转等需要服务层校验和权限测试；数据库约束不是完整业务安全实现。

重复窗口未确认，不自动永久去重。未来微信和手机号多种联系方式可迁移为 lead_contacts；本版保留单个必填微信密文结构。私信原文属于敏感内容，暂不建明文字段，后续使用受限加密存储并确定保存期限。

审计表仅预留结构，当前无防篡改机制；生产分离只追加权限，日志不得记录解密联系方式。迁移采用编号文件，不能依靠 CREATE IF NOT EXISTS 修改已有列。生产选型后转换 SQL、设置备份和恢复演练。
